# 台股策略系統發布檢查清單

## 必做檢查

1. 網頁修改後要同步兩個分支：
   - `main`：保留完整專案與 Apps Script 原始碼。
   - `gh-pages`：公開網站實際讀取的分支。

2. 修改 `web/app.js` 後，要更新 `web/index.html` 裡的 `app.js?v=...` 版本字串，避免瀏覽器或 GitHub Pages 繼續載入舊檔。

3. 發布前要檢查：
   - `node --check 台股策略系統/web/app.js`
   - `git diff --check`
   - 公開網址是否載入最新 `app.js?v=...`

4. 手動「更新資料」會執行完整 Apps Script 刷新，可能接近 30 秒以上；前端逾時不可設太短，目前保留 75 秒。

5. 即使 Apps Script 或 GitHub Raw 短暫失敗，前端也必須：
   - 恢復「更新資料」按鈕。
   - 不停留在「更新中」。
   - 使用目前畫面或備援資料顯示狀態。

6. 資料暫時空白時，前端不可中斷：
   - 沒有最新交易日，顯示模擬起始日。
   - 沒有候選股，顯示「尚無 A 級候選股」。
   - 沒有交易紀錄，顯示「今日暫無交易」。

## 發布後驗證

1. 開啟公開網站並確認 `app.js?v=...` 是最新版本。
2. 按一次「更新資料」。
3. 等待刷新完成後確認：
   - 按鈕文字回到「更新資料」。
   - 最後更新不是「更新中」。
   - 總資產、日期、候選股、持倉、交易紀錄都有正常畫面。

## 這次事故原因

- 程式先推到 `main`，但公開網站實際使用 `gh-pages`，造成網站仍讀舊版。
- 前端等待 Apps Script 只有 30 秒，但完整刷新有時接近或超過 30 秒。
- 舊版前端在逾時或空資料時沒有完整復原畫面狀態。
